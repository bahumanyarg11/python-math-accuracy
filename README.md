# Accuracy of mathematical functions in NumPy, SciPy, JAX and PyTorch

This repository contains the code and data of the report *Accuracy of Mathematical Functions in NumPy, SciPy, JAX and PyTorch, on x86-64 and Arm64 CPUs, an NVIDIA T4 GPU and Apple MPS, in binary64, binary32, binary16 and bfloat16* (Bahumanya R G, 2026; source in `paper/`). It measures the largest error, in ulps, of the elementary and special functions of these four libraries, using the error measure, the special-value rules, the search algorithm and the published worst-case inputs of Gladman, Innocente, Mather, Ozaki and Zimmermann, *Accuracy of Mathematical Functions in Single, Double, Double Extended, and Quadruple Precision* (August 2026).

All binary16 and bfloat16 inputs (and all input pairs for atan2, hypot and pow), and all binary32 inputs of the univariate functions, are tested exhaustively, so those maxima are exact. For binary64 and for the bivariate binary32 functions, the values are lower bounds found with a port of their search algorithm. Every reported maximum was recomputed independently with MPFR by calling the library again on the platform where it was found (`drivers/verify.py`, `drivers/verify_extra.py`; results in `results/verify/`).

## Platforms and versions

Same Python packages everywhere: NumPy 2.2.6, SciPy 1.17.1, JAX and jaxlib 0.11.2 (`jax[cuda12]` on the GPU), PyTorch 2.9.1 (CPU wheel on x86-64, `cu126` wheel on the GPU), `ml_dtypes` 0.5.4.

| tag | platform |
|---|---|
| `x86_cpu` | Kaggle VM, Intel Xeon CPU @ 2.20 GHz (AVX2, no AVX-512), 4 vCPUs, Linux 6.18, glibc 2.39, Python 3.13 |
| `mac_arm64_cpu` | Apple M4, macOS 26.3.1, Python 3.13 |
| `t4_cuda` | NVIDIA Tesla T4 on Kaggle, driver 580.178.04, PyTorch built with CUDA 12.6 |
| `mac_mps` | the GPU of the same Apple M4, through PyTorch's MPS backend (PyTorch only, no binary64) |

## Reproducing

Requirements: a C compiler, GMP and MPFR (e.g. `brew install gmp mpfr` or `apt install libgmp-dev libmpfr-dev`), and the Python packages above plus `gmpy2`.

```bash
scripts/fetch_deps.sh          # CORE-MATH @ 7ebab739 and math_accuracy @ c2b897fb into ext/
harness/build.sh               # builds build/libacc.{so,dylib}: error engine + CORE-MATH references
python3 drivers/probe_denormals.py --tag TAG --device DEV
python3 drivers/exhaustive.py --fmt binary16 --device DEV --tag TAG          # also bfloat16, binary32
python3 drivers/exhaustive.py --fmt binary16 --bivariate --device DEV --tag TAG --funcs pow,atan2,hypot
python3 drivers/search.py --fmt binary64 --device DEV --tag TAG              # binary32 for atan2/hypot/pow
python3 drivers/verify.py --tag TAG --device DEV
python3 drivers/verify_extra.py --tag TAG --device DEV
python3 make_tables.py         # regenerates tables/ and paper/tables/ from results/
```

`DEV` is `cpu`, `cuda` or `mps`. `drivers/run_all.sh TAG DEV` runs the main sequence. All drivers are resumable: a result that already exists is skipped. `gate/run_gate.sh` checks that the error engine reproduces published values of Gladman et al. for GNU libc 2.39 and OpenLibm 0.8.7 on x86-64 Linux (the outputs of our run are in `results/gate/`). The x86-64 and T4 runs were made with private Kaggle kernels generated by `kaggle/make_kernel.py`; the commands are listed in `kaggle/KERNELS.md`.

## Layout of `results/`

| directory | content |
|---|---|
| `binary32/TAG/`, `binary16/TAG/`, `bfloat16/TAG/` | exhaustive univariate results, one JSON per library and function (`LIB_FUNC.json`, final record in `final`) |
| `binary16_bivar/TAG/`, `bfloat16_bivar/TAG/` | exhaustive results over all input pairs for atan2, hypot, pow |
| `binary64_search/TAG/`, `binary32_search/TAG/` | search results (lower bounds) |
| `*/TAG/available.json`, `*/TAG/versions.json` | functions provided by each library on that platform; software versions |
| `verify/TAG.json`, `verify/TAG_extra.json` | independent verification of every maximum, and of the flushed maxima and NaN examples |
| `provenance/` | `denormals_*.json`: flush-to-zero / denormals-are-zero probes (used by `make_tables.py`); `x86_cpu.json`, `t4_cuda.json`: bitwise comparison of each library's outputs with candidate implementations (`drivers/provenance.py`); `cuda_bessel_probe.json`: PyTorch Bessel functions on CUDA per format; `x86_verify_second_instance.json`, `x86_repro_probe_*.txt`: the machine-dependence checks of the paper's Section 6 |
| `validation/` | check of the CORE-MATH fast path against MPFR |
| `gate/` | reproduction of published values of Gladman et al. |

`tables/` contains the tables in Markdown, CSV and LaTeX; `tables/*_inputs.csv` give, for every table cell, the input attaining the maximum, the library output, and the flushed and NaN examples.
